# API Reference — Home Inventory Manager

All routes except `/api/auth/*` require an authenticated session — each route checks this itself (see "Route protection" in `docs/ARCHITECTURE.md`); unauthenticated requests receive `401 Unauthorized`. All request/response bodies are JSON unless noted. `register`, `resend-verification`, the credentials login callback, and `forgot-password` are additionally rate-limited (Upstash Redis) since they're public and unauthenticated — repeated abuse returns `429 Too Many Requests`.

## Auth

### `POST /api/auth/register`
Self-service account creation.
- **Auth required**: no.
- **Rate limited**: yes.
- **Request body**: `{ email: string, password: string }`
- **Behavior**: creates a `User` (unverified, bcrypt-hashed password), creates the five default `Category` rows for that user in the same transaction, generates an `EmailVerificationToken`, and sends a verification email via Resend. Does **not** log the user in or create a session.
- **Response**: `201 { message: "Check your email to verify your account" }`
- **Errors**: `400` invalid email/weak password; `409` email already registered; `429` rate limited.

### `GET /api/auth/verify-email?token=...`
Confirms a registration email.
- **Auth required**: no.
- **Behavior**: validates the token, sets `User.emailVerified`, invalidates the token.
- **Response**: `200` (page redirects to `/login` with a success message).
- **Errors**: `400` invalid/expired/already-used token.

### `POST /api/auth/resend-verification`
Resends the verification email for an unverified account.
- **Auth required**: no.
- **Rate limited**: yes.
- **Request body**: `{ email: string }`
- **Behavior**: if the email matches an unverified account, generates a new `EmailVerificationToken` and sends another verification email. Response is identical whether or not the account exists/needs verifying, mirroring `forgot-password`'s "never reveal account existence" behavior.
- **Response**: `200 { message: "If that account needs verifying, a new link has been sent" }`
- **Errors**: `429` rate limited.

### `POST /api/auth/forgot-password`
Requests a password-reset email.
- **Auth required**: no.
- **Rate limited**: yes.
- **Request body**: `{ email: string }`
- **Behavior**: if the email matches an account, generates a `PasswordResetToken` and sends a reset email via Resend. Response is identical whether or not the account exists, so the endpoint never reveals which emails are registered.
- **Response**: `200 { message: "If an account exists for this email, a reset link has been sent" }`
- **Errors**: `429` rate limited. (Never `404` for an unknown email — see above.)

### `POST /api/auth/reset-password`
Completes a password reset.
- **Auth required**: no.
- **Request body**: `{ token: string, newPassword: string }`
- **Behavior**: validates the token, updates `passwordHash`, marks the token used, invalidates existing sessions for that user.
- **Response**: `200 { message: "Password updated" }`
- **Errors**: `400` invalid/expired/already-used token or weak password.

### `POST /api/auth/[...nextauth]` (and related NextAuth routes: `/api/auth/signin`, `/api/auth/session`, `/api/auth/signout`)
Handled entirely by Auth.js. `signIn("credentials", { email, password })` on the client posts credentials; on success a database session cookie is set.

- **Auth required**: no (this is the login mechanism itself).
- **Rate limited**: yes.
- **Behavior**: in addition to validating the password, the `CredentialsProvider` checks `User.emailVerified` is set — if not, sign-in fails with an `EMAIL_NOT_VERIFIED` error instead of succeeding.
- **Errors**: `401` on invalid credentials or unverified email; `429` rate limited.

## Uploads

### `POST /api/upload`
Issues a short-lived signed token authorizing a direct client-to-Blob upload (via `@vercel/blob/client`'s `handleUpload`).

- **Auth required**: yes.
- **Request body**: Blob client-upload handshake payload (generated by the `upload()` helper — includes intended pathname/content type).
- **Response**: signed client token payload consumed by `@vercel/blob/client` to complete the PUT directly to Blob storage.
- **Errors**: `401` if unauthenticated; `400` if content type isn't an accepted image/PDF type.

## Categories

### `GET /api/categories`
List the current user's categories.
- **Response**: `200 [{ id, name, icon, itemCount }]`

### `POST /api/categories`
Create a category.
- **Request body**: `{ name: string, icon?: string }`
- **Response**: `201 { id, name, icon }`
- **Errors**: `400` invalid/empty name; `409` duplicate name for this user.

### `PATCH /api/categories/[id]`
Rename a category / change its icon.
- **Request body**: `{ name?: string, icon?: string }`
- **Response**: `200 { id, name, icon }`
- **Errors**: `404` not found or not owned by user; `409` name conflict.

### `DELETE /api/categories/[id]`
Delete a category.
- **Response**: `204`
- **Errors**: `404` not found; `409` if items still reference this category (client should prompt to reassign or delete those items first).

## Items

### `GET /api/items`
List items, optionally filtered.
- **Query params**: `categoryId?`, `search?` (matches name/serial number), `warrantyExpiringThisMonth?=1`
- **Response**: `200 [{ id, name, categoryId, category: {name}, purchaseDate, price, warrantyExpiration, serialNumber, location, createdAt }]`

### `POST /api/items`
Create an item, optionally with attachments created in the same request.
- **Request body**: `{ name, categoryId, purchaseDate?, price?, warrantyExpiration?, serialNumber?, location?, notes?, attachments?: [{ blobUrl, fileName, mimeType, sizeBytes, type }] }`
- **Response**: `201` full item object including nested `attachments`.
- **Errors**: `400` validation failure (e.g. missing name/categoryId); `404` if `categoryId` doesn't belong to the user.

### `GET /api/items/[id]`
Fetch one item with its attachments.
- **Response**: `200` item object including `attachments: [{ id, type, blobUrl, fileName, mimeType, sizeBytes }]`
- **Errors**: `404` not found or not owned by user.

### `PATCH /api/items/[id]`
Update item fields (same shape as create, all fields optional).
- **Response**: `200` updated item.
- **Errors**: `400` validation; `404` not found.

### `DELETE /api/items/[id]`
Delete an item and its attachments (DB rows and corresponding Blob objects).
- **Response**: `204`
- **Errors**: `404` not found.

## Attachments

### `POST /api/items/[id]/attachments`
Link an already-uploaded Blob file to an existing item.
- **Request body**: `{ blobUrl, fileName, mimeType, sizeBytes, type: "PHOTO" | "RECEIPT" | "WARRANTY" }`
- **Response**: `201 { id, itemId, type, blobUrl, fileName, mimeType, sizeBytes }`
- **Errors**: `400` invalid type; `404` item not found.

### `DELETE /api/items/[id]/attachments/[attId]`
Remove an attachment (deletes the Blob object and the DB row).
- **Response**: `204`
- **Errors**: `404` not found.

## Settings

### `GET /api/settings`
Fetch the current user's preferences.
- **Response**: `200 { warrantyNotificationsEnabled: boolean }`

### `PATCH /api/settings`
Update preferences.
- **Request body**: `{ warrantyNotificationsEnabled: boolean }`
- **Response**: `200 { warrantyNotificationsEnabled: boolean }`

## Account

### `PATCH /api/account/password`
Change password for the currently authenticated user — distinct from the public `forgot-password`/`reset-password` flow.
- **Request body**: `{ currentPassword: string, newPassword: string }`
- **Response**: `200 { message: "Password updated" }`
- **Errors**: `400` current password incorrect (`field: "currentPassword"`) or new password too weak; `401` unauthenticated.

## Common error shape

All error responses use:
```json
{ "error": { "message": string, "field"?: string } }
```
`field` is present for validation errors to indicate which input failed.
